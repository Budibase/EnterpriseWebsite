## Give access requests a clear decision path

Access requests need a clear justification, a policy check, and an accountable approver. This template brings those steps together so employees can request access and reviewers can see the recommendation, reasoning, and decision history in one place.

## How it works

A user submits an access request via form or chat. The agent checks the requester in Okta or Azure AD.

Policies and role tables determine if approval is required. The agent explains why it recommends approval or denial.

A manager or admin confirms the decision. Permissions are added or removed in IAM systems.

The decision is logged and sent to Slack/Teams.

## Where people stay in control

People remain responsible for final approval; exceptions; sensitive system access. The agent produces a recommendation; a human approver makes the access decision.

## Adapt it to your organization

Connect the systems listed alongside this description and configure the workflow for your organization’s data, permissions, and policies. Review the named agents, apps, and automations before using them with your own records.
