## Give password resets a safe next step

Handle password-reset requests with the requester and policy context needed to act safely. The agent validates the request, identifies the appropriate reset path, and routes sensitive or ambiguous cases for review.

## How it works

A requester submits a password reset request through Slack, Teams, or the Password Reset Request Form, creating a tracked request row. The agent confirms the request type, retrieves context from Okta and the service desk, checks the relevant policy source, and asks for any missing details in chat.

Where policy permits, the agent completes standard self-service resets where policy and identity checks pass and records the outcome without waiting for manual handling. The agent escalates privileged accounts, third-party requests, failed identity checks, or applications marked as sensitive to the responsible owner with a decision summary and supporting context.

An approver reviews the escalation in chat or the IT Reset Review Queue, then approves, rejects, or returns it for more information.

## Where people stay in control

People remain responsible for approval exceptions; risky or ambiguous requests.
