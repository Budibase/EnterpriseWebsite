## Resolve routine resets and escalate sensitive ones

Help the service desk distinguish self-service password resets from requests that require admin approval. The agent checks the requested app and user assignment in Okta, sends a reset link for SWA apps, and escalates SSO-style resets.

## How it works

A user submits a request through a form tied to the Password Requests table. The agent looks up the app in Budibase and retrieves the corresponding user in Okta.

The workflow verifies that the requester is actually assigned to the target application. SWA apps get a self-service reset link, while SSO-style apps are escalated for manual approval.

The original Password Requests row is updated with an approved, denied, or escalated decision and rationale. All outcomes are logged on the Decisions table, and approved SSO requests can later trigger the Okta reset flow.

## Where people stay in control

People remain responsible for manual approval for SSO and SAML applications; denying escalated requests; reviewing exceptional security-sensitive cases.
